# ADR-0006：原生实体重力与角色重力帧所有权

- 状态：已实现第一阶段，等待 PR 验收
- 日期：2026-08-04

## 背景

现有 `PrimaryGravity` 位于 ballistics 内，局部重力源由 GDScript
`MaterialWorld` 持有。这样弹体、角色和镜头不能共享同一个确定性重力采样入口，
高速实体也只能在单个固定步起点采样一次。

## 决策

- C++ `GravityField` 是实体重力的唯一计算权威，包含一个主坠核和按稳定 ID 排序的
  局部场。
- 主坠核继续使用表面内均匀球模型、表面外平方反比模型；局部场第一版只允许有界
  径向线性衰减场和有界常向量场。
- 重力源命令、tick 生命周期和采样批使用独立 `gravity_transport_dto_version = 1`；
  material DTO v1、材质编号、64×64 区块协议不变。
- 每个实体固定步可以按确定性空间间距拆成多个重力子步；子步数有固定上限，不能
  依赖墙钟时间或帧率。
- Godot 继续负责角色碰撞、输入和表现。角色各项物理行为读取同一份 `GravityFrame`；
  镜头只能读取角色的 `up`，不得查询或写入权威重力。
- P3 固定向下 `SAND↔AIR` 规则仍使用网格 `+Y`，本 ADR 不把材质运动切换为径向重力。
- 在未完成跨语言等价验证前，GDScript 重力参考和 fallback 路径必须保留。

## 后果

- ballistics 与未来角色查询共享一个 native field，不再复制主坠核公式。
- 局部星种源在迁移期间可以同时镜像到 Native 和尚未迁移的 `MaterialWorld`；材质玩法
  不会因为实体重力迁移而改变权威。
- GravityField 的 checksum、tick 和稳定源顺序可用于双宿主重放；跨语言桥接在后续 PR
  中批量传输，不提供逐像素或逐实体回调接口。
- 区块激活调度不属于本 ADR；在 P3 提供真实 activation batch 前，调试叠层只能报告
  dirty chunks 并明确标注其含义。
