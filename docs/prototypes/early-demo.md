# 早期物理 Demo

## 验证目标

本 Demo 不是正式关卡，也不验证剧情完成度。它把三个最高风险问题放进同一间小沙盒：

1. 玩家能否快速读懂“下方指向坠核”的径向重力；
2. 沙、液体、气体和热反应是否能产生清晰的局势变化；
3. 星种作为临时引力源，是否能让物质改轨并形成有意义的构筑想象。

## 临时实现

Demo 使用 160 × 90 单元的 GDScript 元胞自动机，并以 4 倍最近邻缩放显示。该实现用于快速试错，不改变 ADR-0001：正式权威模拟仍归 C++20 `sim_core` 所有。

迁移到 C++ 前应先记录：每个模拟步的活跃单元数、平均帧时间、最坏连锁反应耗时、星种源数量与玩家可读性反馈。GDScript 原型确认规则后，按命令批、事件批和脏区块批迁移，不复制逐像素 Godot API 调用。

## 操作

- `A / D`：沿星体表面移动
- `W / Space`：跳跃
- `Shift`：朝光标方向推进
- `鼠标左键 / F`：发射当前星种
- `鼠标右键`：采掘岩石、砂和金属
- `1–3 / 鼠标滚轮`：切换引核星种、蒸汽矛和斥裂核
- `R`：重置世界

本文件继续记录底层物质与重力验证；完整胜负闭环、敌人和资源循环见 [`gameplay-demo.md`](gameplay-demo.md)。

## 验收观察

- 角色在星体不同侧面时，“下方”始终朝向坠核。
- 砂和液体会沿径向坡面重新分布，烟和蒸汽逆重力移动。
- 水接触熔质后形成岩石与蒸汽；火能点燃油，水能抑制火。
- 星种飞行时受主坠核影响，锚定后短暂吸引周围物质。
- 连续投放物质和三枚星种时，演示仍能响应输入。

## 当前性能基线

2026-07-16 使用官方 Godot 4.6.3 Linux Standard 在无窗口环境测试：160 × 90 网格、三处动态重力源、额外投放 24 组动态物质，连续 300 帧平均约 **46.2 FPS**，期间完成 199 个模拟步，固定 30 Hz 模拟没有掉速。

这是容器中的相对基线，不代表玩家设备帧率。原始逐像素 `Image.set_pixel()` 上传只有约 6.6 FPS；改为常驻 RGBA 字节缓冲并批量上传后，压力场景提升约 7 倍。下一阶段应继续引入活跃区块和脏区纹理，不能依赖缩小世界掩盖瓶颈。
