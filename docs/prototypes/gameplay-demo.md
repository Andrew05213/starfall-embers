# 可玩玩法 Demo

## 定位

这个 Demo 是《坠星余烬》的第一块可重复试玩垂直切片，目标不是还原井星剧情，而是在一张 640 × 360 的小星体竞技场中验证以下问题：

1. 径向重力下的移动、跳跃和推进是否清楚可控；
2. 星种能否同时承担伤害、控场、环境改造和任务钥匙；
3. 采掘—补充物质—释放星种的资源循环是否会迫使玩家观察环境；
4. 敌人的身体材料与弱点是否能通过颜色、受击反馈和环境反应被理解；
5. 一局短流程能否形成明确目标，而不退化成无目的物理沙盒。

## 单局闭环

`观察敌人 → 选择星种 → 战斗或利用环境 → 回收坠核尘 → 激活地维稳定器`

- 场内生成五只敌人，玩家只需击败其中三只；
- 每只敌人死亡后留下物质并补充玩家储量，同时贡献一份坠核尘；
- 三份坠核尘解锁右上方的地维稳定器；
- 稳定器只接受引核星种，命中后完成本局；
- 生命归零时本局失败，按 `R` 立即重开。

## 三种最小构筑

| 按键 | 构筑 | 主要作用 | 资源消耗 |
| --- | --- | --- | --- |
| `1` | 引核星种 | 撞击后锚定并形成吸引场；也是稳定器钥匙 | 核力 30、物质 12 |
| `2` | 蒸汽矛 | 碰撞释放水与蒸汽；对油体、孢子有额外伤害 | 核力 24、物质 16 |
| `3` | 斥裂核 | 形成短暂排斥场，并推开范围内敌人 | 核力 38、物质 20 |

这三种构筑不是正式星铸器界面，而是核、质、律、触、连系统的固定样本。后续应把它们拆成可组合组件，当前阶段先验证输出是否值得继续深化。

## 敌人与材料关系

- **岩壳体**：生命较高，对普通撞击有减伤，适合用环境、连续场或控位处理；
- **油体**：移动较快，接触火、熔质、蒸汽时承受额外伤害，死亡会留下油；
- **孢子体**：生命较低、追击快，怕火、熔质和蒸汽，死亡释放气态物质。

敌人仍是早期抽象图形，没有正式 AI、骨骼或美术资源。它们的职责是证明“身体材料决定战术”，而不是提供最终战斗手感。

## 资源与操作

- 生命上限 100，归零失败，无被动恢复；
- 核力上限 120，接触地面时恢复较快，空中恢复较慢；
- 按住 `Shift` 朝光标推进，持续消耗核力；
- 星种同时消耗核力和物质；
- 按住鼠标右键采掘光标方向的岩石、砂和金属，将其转为物质储量；
- 物质储量上限 100，迫使玩家在攻击节奏和环境破坏之间做选择。

## 自动验证

```bash
godot --headless --path game --script res://tests/demo_smoke.gd
godot --headless --path game --script res://tests/gameplay_smoke.gd
godot --headless --path game --script res://tests/demo_benchmark.gd
```

`gameplay_smoke.gd` 会验证敌人生成、玩家受伤、地形采掘、击杀奖励、目标解锁、错误星种拒绝和胜利状态闭合。

2026-07-16 在当前 Linux 容器中独占运行压力基准：五只玩法敌人、三处额外重力源和 24 组动态物质同时存在时，300 帧平均约 **47.1 FPS**，期间完成 191 个固定模拟步。该数据只用于版本间相对回归，不代表玩家设备帧率。

## 已知边界

- 当前仍使用 GDScript 全网格模拟，正式性能方案尚未迁移到 C++ 区块核心；
- 敌人碰撞和寻路使用廉价采样，不代表正式生态 AI；
- 没有正式星铸器 UI、背包、存档、声音、美术资产或井星关卡；
- 平衡数值只服务于 3–8 分钟试玩，不冻结为正式数值；
- 下一轮应以真人试玩记录验证死亡原因是否可读、三种构筑的使用率、资源断档频率和完成时长。
